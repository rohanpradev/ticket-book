# Research and primary sources

Reviewed on 15 October 2026. Current registry metadata was checked before updating dependencies, and the installed lockfile was verified with type checks, real service tests, and production builds. The project uses Vite+ 1.2.0, Hono 4.13.13, Drizzle 0.45.4, React 19.3.1, ioredis 6.0.0, and TypeScript 7.0.2. The container and CI runtime is Bun 1.4.3; host checks also run on Bun 1.4.2.

The useful standard is a documented mechanism plus an executable check, rather than a long list of infrastructure names.

The architecture guide records the project's own decisions and limitations. The benchmark is the source of performance evidence; these references are not a substitute for measurements of this implementation.

## Additional standards research

Knip 6.41.0 was checked against the current package registry and integrated with the existing Vite+ configuration. [Knip’s Vite+ plugin](https://knip.dev/reference/plugins/vite-plus) discovers build inputs; subprocess crash fixtures are declared entry points. [TypeScript indexed access](https://www.typescriptlang.org/tsconfig/noUncheckedIndexedAccess.html) and [exact optional properties](https://www.typescriptlang.org/tsconfig/exactOptionalPropertyTypes.html) expose absent-value assumptions. [Zod’s official parsing guidance](https://zod.dev/basics) informs the shared runtime contracts. [Bun audit](https://bun.com/docs/pm/cli/audit) checks the lockfile; it is a known-advisory check, not proof that dependencies are vulnerability-free. [GitHub’s secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use) informs full-SHA action pins and read-only CI permissions. Action hashes were resolved from the official repositories’ corresponding release tags.
